Technique Overview

ClickFix is a social-engineering technique in which a web page convinces the user to copy a command and run it themselves — typically in the Windows Run dialog (Win+R) or the macOS Terminal — under the cover of a fake error message, a bogus CAPTCHA, or a counterfeit software-update prompt. MITRE catalogues it as T1204.004, User Execution: Malicious Copy and Paste, added to ATT&CK on 18 March 2025 and last revised 12 May 2026.

Its significance is structural rather than technical. Most initial-access controls in a modern enterprise are built around inspecting things that arrive — attachments, downloads, scripts fetched by a browser. ClickFix delivers nothing. There is no attachment to detonate, no download to reputation-check, no browser exploit to sandbox. The payload crosses the security boundary through the user's clipboard and is executed by the user's own hand, in a shell the user is trusted to use. Email filtering, browser sandboxing, download protections and mark-of-the-web all sit to one side of the transaction and never see it.

That structural advantage has produced explosive adoption. Observed use surged 517% in the first half of 2025, and by 2026 the technique accounted for roughly 8% of all blocked attacks and ranked among the top global malware-delivery methods between March and May. Critically, adoption crosses the usual tiering: this is simultaneously the delivery mechanism for commodity infostealers sold on Telegram and for state programmes in Russia, Iran, North Korea and Pakistan. Techniques rarely span that range; ClickFix does because its cost is near zero and its defeat rate against conventional controls is high.

The technique has also proven unusually generative. Rather than a single static pattern, it has spawned a family of derivatives — FileFix, PromptFix, ConsentFix, TerminalFix, DownloadFix — each relocating the paste target to a less-monitored interface as defenders instrument the previous one. Its internals have moved in parallel, from cleartext commands and disk-based .bat files to fileless, memory-only execution with XOR or Base64+Deflate encoding and server-side polymorphism. Defensive response has begun: Apple shipped a macOS mitigation in March 2026, and a bypass using the applescript:// URI scheme appeared within roughly a month.

Classification Note

ClickFix is a delivery and execution technique, not a malware family or an actor. It is the step that gets code running; what runs afterwards is unconstrained and varies by operator (Section 06).

Distinguish it from adjacent techniques it is often conflated with: it is not phishing-with-attachment (T1204.002 — there is no file), not drive-by compromise (T1189 — there is no browser exploit), and not a browser vulnerability of any kind. The browser behaves correctly throughout. The only thing "exploited" is the user's willingness to follow instructions, which is why no patch addresses it.

"ClickFake" appears in reporting on the DPRK Contagious Interview cluster and denotes a campaign applying this technique, not a separate technique.

02
Execution Mechanics The canonical Windows chain; variants relocate step 03
01
Lure Delivery
The victim reaches an attacker-controlled page — via malvertising, a compromised legitimate site, SEO poisoning, a phishing link, or in targeted operations a fake job-interview or recruitment portal. Modern lures perform browser and OS fingerprinting first, serving the correct instructions for the victim's platform and suppressing the lure entirely for analysis environments.
02
Pretext — Manufactured Failure
The page presents a problem only the user can "fix": a failed CAPTCHA ("verify you are human"), a corrupted document, a browser or driver update, a Windows Update screen, or a broken video codec. The pretext is essential — it converts an unusual request (open a shell and paste this) into a plausible remediation step. Recent lures add countdown timers and video walkthroughs to compress deliberation and supply false legitimacy.
03
Clipboard Poisoning
JavaScript writes the payload command to the clipboard automatically — the user is never shown the real command and typically believes they are copying a verification code or error reference. The visible instruction is only "press Win+R, press Ctrl+V, press Enter." Displayed text and clipboard contents routinely differ.
04
User-Performed Execution
The victim pastes into the Run dialog (Windows), Terminal (macOS), or the Alt+F2 run prompt (Linux) and executes. This is the security boundary crossing, and it is performed by an authorised user in an interface they are permitted to use. Commands commonly invoke powershell, mshta, rundll32, wscript, curl or wget, frequently with padding whitespace so the malicious portion scrolls out of the dialog's visible field.
05
Fileless Staging
Contemporary chains avoid touching disk. The pasted command retrieves a second stage — increasingly over DNS or from a legitimate hosting service — decodes it in memory via XOR or Base64+Deflate, and executes without writing an artifact for disk-scanning AV to examine. Server-side polymorphism returns a structurally different payload per request, defeating hash- and string-based signatures.
06
Payload & Persistence
The final payload lands (Section 06) and establishes persistence by conventional means. Note the forensic consequence of steps 03–04: the pasted string is written to the RunMRU registry key before any deobfuscation — the single highest-value artifact this technique leaves behind (Section 08).
03
Variant Family Each derivative relocates the paste target to a less-instrumented interface
FileFix Windows File Explorer address bar
Moves execution out of the Run dialog and into File Explorer, instructing the victim to paste a command or path into the address bar. Significant because it defeats the single most effective ClickFix mitigation — disabling the Run dialog — and because File Explorer address-bar input is far less commonly monitored, with no direct RunMRU equivalent to capture the pasted string.
PromptFix AI assistants and agentic tooling
Retargets the technique at AI tooling, embedding instructions intended to be relayed through or executed by an assistant rather than typed by a human. Notable as the first variant that does not require a human in the loop at the execution step — the trust being abused is the user's trust in their assistant's output.
ConsentFix OAuth consent flows
Applies the same manufactured-failure pretext to OAuth authorisation, steering the victim into granting application consent rather than executing a command. The outcome is token-based account access instead of code execution — the technique's logic transplanted into identity, where no endpoint control applies at all.
TerminalFix / DownloadFix Terminal emulators · browser download flows
Further relocations of the execution surface documented by Push Security among newer variants that combine OS detection, video walkthroughs and countdown timers. The pattern across the family is consistent: as defenders instrument one interface, the technique migrates to the next least-monitored one.
macOS applescript:// bypass URI scheme handler
After Apple shipped a ClickFix-targeted mitigation in March 2026, a modified variant surfaced within roughly a month using the applescript:// URI scheme to achieve execution without invoking Terminal at all — sidestepping both the new mitigation and Terminal-focused detection analytics such as AN0964.
04
Evolution Timeline
~2024
Emergence — Fake Errors and Cleartext Commands
The technique appears in commodity campaigns using fake browser-update and error-message lures, with cleartext commands and disk-based .bat payloads. Early implementations are crude and leave abundant disk artifacts.
2025-03-18
Formalised as ATT&CK T1204.004
MITRE adds "User Execution: Malicious Copy and Paste" as a sub-technique of T1204, giving defenders a shared identifier and, importantly, a mapping target for detection engineering. Platforms listed: Windows, macOS, Linux.
H1 2025
517% Surge — Mass Adoption
Observed use increases more than sixfold in six months. Adoption broadens from commodity infostealer operators into state-aligned programmes, and the technique settles at roughly 8% of all blocked attacks.
2025 → 2026
Fileless Execution & Server-Side Polymorphism
Operators abandon cleartext and disk-based staging in favour of XOR or Base64+Deflate encoding decoded entirely in memory, defeating disk-scanning antivirus. Menlo documents the shift to server-side polymorphism, where each request returns a structurally different payload, collapsing signature-based coverage.
2026 (early)
Variant Family Proliferates
FileFix, PromptFix, ConsentFix, TerminalFix and DownloadFix emerge, relocating execution into File Explorer, AI tooling, OAuth consent and terminal emulators. Lures add OS detection, countdown timers and video walkthroughs.
2026-03
Apple Ships a macOS Mitigation
Apple adds a platform-level mitigation specifically targeting ClickFix-style attacks — a rare instance of an OS vendor shipping a control against a social-engineering technique rather than a vulnerability.
2026-04
Mitigation Bypassed via applescript://
Within roughly a month, a modified variant uses the applescript:// URI scheme to bypass the Terminal requirement entirely. The turnaround time is the clearest available measure of how cheap it is to relocate this technique's execution surface.
2026-03 → 05
Top Global Malware Delivery Technique
ClickFix ranks among the leading malware-delivery methods worldwide for the period, with Microsoft documenting dedicated macOS campaigns using fake utility lures to deliver infostealers.
2026-05-12
ATT&CK Entry Revised to v1.1
MITRE updates T1204.004 with expanded procedure examples — including Contagious Interview (G1052), Kimsuky (G0094) and MuddyWater (G0069) — and three platform-specific detection analytics.

The analytic point of this matrix is the spread, not the entries. Four state programmes across four countries and the entire commodity infostealer ecosystem converged on the same technique inside roughly two years. That does not normally happen — capability usually flows downward from state tooling to criminal use over a longer horizon, or stays tier-locked. ClickFix travelled instantly in both directions because it requires no exploit, no tooling investment and no infrastructure beyond a web page, so there is nothing to reverse-engineer or buy. For defenders the practical consequence is that a ClickFix detection provides no attribution signal whatsoever — the same artifact is produced by a Telegram-bought stealer and by the GRU.

06
Payloads & Outcomes What lands once the paste succeeds
Lumma Stealer Infostealer · Commodity
Among the most frequently observed ClickFix payloads. Harvests browser credentials, session cookies, and cryptocurrency wallet material. Represents the dominant commodity outcome: rapid credential theft monetised through log marketplaces rather than hands-on intrusion.
AMOS (Atomic macOS Stealer) Infostealer · macOS
The primary macOS outcome, documented by CloudSEK in ClickFix campaigns and by Microsoft in fake-utility lure campaigns (May 2026). Its prominence is why ClickFix matters on macOS specifically — the technique neatly sidesteps Gatekeeper and notarisation, which govern downloaded applications rather than user-pasted shell commands.
Latrodectus Loader · Commodity
Loader family frequently delivered through ClickFix chains, functioning as the staging layer for follow-on tooling including ransomware precursors. Its presence marks a chain intended for hands-on-keyboard follow-up rather than one-shot credential theft.
NetSupport RAT RAT · Repurposed Legitimate Tool
Legitimate remote-administration software repurposed as a RAT. Pairs naturally with ClickFix because both halves of the chain rely on things that are individually legitimate — a user running a command, and a signed remote-support tool — leaving little that is inherently malicious for signature-based controls to flag.
FreakyPoll State Tooling · Sandworm
Delivered in Sandworm's use of the technique since spring 2026, resulting in confirmed network compromise of at least one organisation. Illustrates the ceiling: the same paste that usually yields a commodity stealer can equally yield GRU access to a network.
Havoc C2 Framework C2 Framework · S1229
Open-source post-exploitation framework whose infection chains are ATT&CK-documented as initiated via ClickFix lures in phishing emails — the technique feeding directly into full command-and-control rather than a single-purpose payload.
07
Why It Works The specific control failures this technique exploits
Nothing Crosses the Inspection Boundary Control Architecture
Email gateways, browser sandboxes, download reputation services and mark-of-the-web all operate on artifacts in transit. ClickFix transmits no artifact — the payload travels as clipboard text inside the user's session and is instantiated locally. This is not a control being evaded; it is a control never being invoked, which is why adding more inspection depth produces no improvement.
The Executing Identity Is Legitimate Authorisation Model
Execution is performed by an authenticated, authorised user in an interface they are entitled to use. There is no privilege escalation, no anomalous account, no unusual logon — the process ancestry looks like a person running a command, because it is. Behavioural detection must therefore distinguish legitimate from illegitimate use of a legitimate capability, which is a materially harder problem than spotting an unauthorised one.
Displayed Text ≠ Clipboard Contents Interface Trust
JavaScript populates the clipboard with content the user never sees. Security awareness training that teaches users to "read before you click" fails structurally here: there is nothing to read. The user believes they are copying a verification code. Whitespace padding compounds this by pushing the malicious portion out of the Run dialog's visible field even if they look.
Verification Fatigue as an Attack Surface Human Factors
Users are conditioned by years of legitimate CAPTCHAs, MFA prompts and update nags to perform small compliance rituals without scrutiny. SentinelOne frames this as weaponised verification fatigue. The pretext succeeds not because users are careless but because it is indistinguishable in form from the dozens of legitimate interruptions they are trained to clear quickly.
Self-Blame Suppresses Reporting Incident Response
Because the victim performed the action personally, realisation tends to arrive with embarrassment attached — a materially different psychology from "I received a phishing email," which users report readily. This suppresses and delays reporting, extending dwell time. Any defensive programme against this technique should explicitly address reporting culture, not just prevention.
Near-Zero Cost to Relocate Defender Economics
The technique requires no exploit, no tooling and no infrastructure beyond a web page, so moving to a new execution surface costs an afternoon. The variant family and the ~1-month turnaround on Apple's March 2026 mitigation are the evidence. Defenders instrumenting a specific interface (the Run dialog) are entering an exchange where each of their moves is expensive and each of the adversary's is cheap.
08
Detection Artifacts, queries and hunting guidance

The highest-fidelity artifact on Windows is the RunMRU registry key — HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\RunMRU — which records every command entered into the Run dialog as single-letter values, with execution order tracked in MRUList. Values terminate in a literal \1, so entries appear as notepad\1 or mshta.exe\1.

Its forensic value is specific and worth understanding: RunMRU captures the pasted string before any downstream deobfuscation. It is the closest thing available to a transcript of the social-engineering step itself, and it distinguishes successful execution from a lure that was merely displayed. Where a memory-only chain leaves nothing else behind, this key frequently survives.

RunMRU modification containing LOLBins · Microsoft Defender XDR (KQL, illustrative)
// Pattern is well documented (Microsoft; Bert-JanP Hunting-Queries repo; kqlquery.com); // this composition is analyst-authored. DeviceRegistryEvents | where RegistryKey endswith @"\Explorer\RunMRU" | where RegistryValueData has_any ("powershell","mshta","rundll32","wscript", "cscript","curl","wget","cmd /c","iwr","irm") or RegistryValueData has_any ("http://","https://") | project Timestamp, DeviceName, InitiatingProcessAccountName, RegistryValueName, RegistryValueData | order by Timestamp desc
Published Sigma rule · Windows registry_set
SigmaHQ — "Potential ClickFix Execution Pattern - Registry" Path: rules/windows/registry/registry_set/registry_set_potential_clickfix_execution.yml Logic: detects RunMRU key modifications whose value data contains HTTP/HTTPS links — i.e. a pasted command referencing a remote resource. Use this as the baseline rule rather than authoring from scratch.
Browser-parented shell execution · EDR process telemetry (illustrative)
// Explorer.exe spawning an interpreter shortly after browser activity is the // behavioural signature when RunMRU is unavailable (e.g. FileFix variants). process_create | where parent_process in ("explorer.exe") | where process_name in ("powershell.exe","mshta.exe","wscript.exe", "cscript.exe","rundll32.exe","curl.exe") | where command_line has_any ("-enc","-e ","FromBase64String","DownloadString", "IEX","Invoke-Expression","hidden","-w h") | join kind=inner (browser_activity | where timestamp > ago(10m)) on device_id
macOS / Linux terminal chains · ATT&CK analytics AN0963 · AN0964
MITRE publishes three platform-specific analytics for T1204.004: AN0962 (Windows) — browser/email activity → process creation with suspicious arguments → optional file drop → outbound connection AN0963 (Linux) — curl/wget piping to bash, or base64 decode chains, followed by transient files and egress AN0964 (macOS) — Terminal/iTerm2 spawning shells with obfuscated patterns, user-directory file writes, network connections Note the coverage gap: AN0964 keys on Terminal/iTerm2, which the April 2026 applescript:// variant specifically avoids.

Known limitations, stated plainly. RunMRU-based detection covers the classic Run-dialog pattern and nothing else — FileFix defeats it entirely, since File Explorer address-bar input has no equivalent MRU capture. Legitimate administrative use of the Run dialog generates false positives in environments where engineers work that way, so the LOLBin and URL conditions are doing the real filtering. Server-side polymorphism means the second-stage payload will not match hashes or static strings, so detection must anchor on the paste event and process ancestry rather than on what lands afterwards. Finally, none of these artifacts are attributional (Section 05).

09
Hardening & Mitigation Rated by how much of the technique each control actually removes
Disable the Run Dialog via GPO HIGH IMPACT
The single most effective control against classic ClickFix, and the one Huntress and others rank first. It removes the execution surface the canonical chain depends on rather than trying to detect its misuse. Most users in most organisations have no business need for Win+R, so the operational cost is typically low — but scope it, since engineering and IT staff will notice immediately.
User Configuration → Administrative Templates → Start Menu and Taskbar → "Remove Run menu from Start Menu" (also disables the Win+R shortcut) Caveat: does NOT stop FileFix, which relocates execution to the File Explorer address bar specifically to survive this control.
Constrain Interpreters with AppLocker / WDAC HIGH IMPACT
Blocking or tightly scoping the interpreters ClickFix commands invoke attacks the chain one step later than the Run dialog, and therefore survives variant relocation — FileFix, TerminalFix and DownloadFix still have to reach an interpreter. Restricting mshta.exe and wscript.exe is comparatively low-friction in most estates; PowerShell needs more care.
Restrict via AppLocker or Windows Defender Application Control: mshta.exe, wscript.exe, cscript.exe Block execution of powershell.exe and mshta.exe from user-writable directories. ATT&CK mitigation: M1038 (Execution Prevention)
PowerShell Constrained Language Mode PARTIAL
MITRE's named mitigation for this technique. Strips the language elements most download-and-execute one-liners depend on, which meaningfully raises the cost of the PowerShell path. Rated partial rather than high because it addresses one interpreter among several — an operator who meets it simply pivots to mshta, curl or a script host.
ATT&CK mitigation: M1038 (Execution Prevention) Deploy via WDAC policy or __PSLockdownPolicy where WDAC is not available.
Targeted User Education — One Specific Rule PARTIAL
Generic "be suspicious" training fails here because the clipboard contents are invisible (Section 07). What does transfer is a single categorical rule with no judgement required: no legitimate CAPTCHA, error message or software update will ever ask you to paste a command into a terminal or Run box. Pair it explicitly with blame-free reporting, since self-blame measurably suppresses disclosure after the victim has executed the command themselves.
Teach the categorical rule, not the judgement call. Reinforce that reporting after execution carries no penalty — dwell time after a successful paste is driven largely by reporting delay.
Web Content & Network Controls PARTIAL
MITRE lists network intrusion prevention (M1031) and restricting web-based content (M1021). These interdict lure delivery and second-stage retrieval rather than the technique itself, so their effectiveness tracks how well your blocklists keep pace with malvertising and newly registered lure domains — which is to say, partially. Egress filtering on the second-stage fetch is the more durable half.
ATT&CK mitigations: M1031 (Network Intrusion Prevention), M1021 (Restrict Web-Based Content)
Clipboard Monitoring WEAK
Intuitively appealing — the clipboard is where the payload lives — but poor in practice. Clipboard telemetry is noisy, privacy-sensitive, inconsistently available across platforms, and trivially defeated by delivering the payload in fragments or via a different transfer path. Worth logging for post-incident reconstruction; not worth building prevention on.
Consider enabling Run-dialog and clipboard logging for forensic value only. Do not treat as a preventive control.
