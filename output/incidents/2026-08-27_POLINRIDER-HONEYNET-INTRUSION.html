01
Situation Overview

On 27 August 2026 a Fortune 500 enterprise CTI team, working inside a Deception.Pro instrumented honeynet, installed a trojanized Python package (pybitjs) on a decoy corporate workstation and waited. Within roughly three hours a live DPRK-linked operator found the callback, engaged it, and began working the host by hand. Over the following week — about 167 hours in total — that operator ran a complete supply-chain intrusion end to end while every process, packet and decrypted C2 exchange was recorded.

What makes this case file worth keeping is not the malware, which is consistent with tooling already documented across the PolinRider campaign. It is the observation conditions. Most intrusion reporting is reconstructed after the fact from surviving artifacts, with the gaps filled by inference. Here the defenders held full telemetry before the adversary arrived, so the record includes things post-hoc forensics normally destroys or never captures: the exact interval between bait and engagement, a three-day dormancy followed by a precise return, and the specific moments where a human being was demonstrably typing rather than a script running.

Three actions in particular mark live hands-on-keyboard work rather than automation: an interactive reboot command (shutdown /r /t 0) issued minutes after first execution, a machine-wide Python 3.14 installation driven through PowerShell on the operator's return, and a deployment script invoked with an argument (SvcHostUpdate.py --deploy) rather than a fixed command line. Each of these is a decision, not a payload step.

The operator's persistence tradecraft is the other durable lesson. All three mechanisms planted — a scheduled task, a registry Run key, and a Startup-folder launcher — were given the same name, MicrosoftCLROptimization, impersonating a genuine Microsoft .NET runtime optimisation component. In this environment that choice was irrelevant because the instrumentation flagged the writes regardless. In a normal enterprise, reviewed by a human scanning a task list, it is exactly the sort of name that survives.

02
Background & Context

The campaign. PolinRider is a DPRK-linked software supply-chain campaign that surfaced in early 2026 and has expanded aggressively across open-source ecosystems. Socket's reporting (July 2026) counted 162 malicious artifacts across 108 packages — roughly 80 Go modules, 10 Packagist packages, npm packages, and a Chrome extension — while OpenSourceMalware tracked confirmed repository compromise reaching 1,951 repositories across 1,047 distinct owners by May 2026 and a confirmed footprint growing roughly 6.5× since March. The campaign's centre of gravity is GitHub account takeover rather than registry compromise: npm and PyPI were comparatively spared precisely because they require separate publishing credentials the operators frequently did not hold.

The delivery tradecraft. PolinRider plants obfuscated JavaScript loaders into legitimate repositories, hidden in configuration files or, in more recent variants, inside fake .woff2 font files triggered through VS Code tasks.json task configurations. Concealment is unusually deliberate for a supply-chain operation: Git history rewriting with force pushes, anti-dated commits so malicious changes appear older than they are, and whitespace padding that pushes code beyond typical screen width in a diff view. Payloads are retrieved from public blockchain RPC infrastructure — TRON, Aptos and BNB Smart Chain services — decrypted with embedded XOR keys and executed via eval(), which puts C2 retrieval on infrastructure most enterprises will not block.

The parent actor. PolinRider is attributed to Famous Chollima, the DPRK cluster this project profiles under the designation WaterPlum (MITRE G1052, "Contagious Interview") — the same operation formally attributed by a seven-nation joint government advisory on 18 September 2026 to the 313 General Bureau of North Korea's Munitions Industry Department. Some reporting additionally claims overlap with APT37 (Reaper / ScarCruft); that overlap is not currently reflected in the companion actor card and is flagged in Section 08 as an open item.

The collection environment. Deception.Pro operates instrumented Active Directory honeynets built to be indistinguishable from real corporate estates — in this case roughly 2,500 endpoints and 2,000 users, with AI-generated and randomised personas, organisations and documents supplying the supporting fiction. The decoy in this engagement was a Product Manager at a fictional global travel company. Sensor coverage combined LimaCharlie EDR, Zeek, and Suricata with ETPRO signatures, plus full packet capture and TLS-decrypted command and control. That last capability is what separates this record from network-flow-based reporting: the C2 exchanges were read, not merely counted.

Kill Chain Narrative Visibility was total by design — see Section 05 for why that inverts the usual reading
Bait Placement & Operator Discovery DETECTED — BY DESIGN
The CTI team installed the trojanized pybitjs-0.1.0 package on the decoy workstation and allowed the resulting callback to reach live attacker infrastructure. Roughly three hours later an operator engaged the host. That interval is the single most operationally interesting number in this case file: it implies the actor is actively monitoring callbacks from installed packages and triaging them by hand on a short cycle, rather than harvesting output from an automated collection queue at leisure.
Analytic note: three hours is an engagement time, not a detection time. It measures the adversary's attentiveness, which is rarely measurable at all outside a deception environment.
27 Aug 14:33 — Loader Execution & Multi-Channel Staging DETECTED
A Node.js loader executed from the malicious package and beaconed to C2 at 23.27.13[.]135. Within the same minute, cmd.exe and curl retrieved the follow-on payloads SvcHostUpdate.py and SvcHostUpdate.js from files.catbox[.]moe, while the loader also chained through a raw README on gitlab[.]com as a secondary delivery channel.
Using a public paste/file host and a raw file in a code-hosting repository as delivery channels places both retrievals inside traffic categories most enterprises permit by default.
27 Aug 14:33 — Interactive Reboot (First HOK Marker) DETECTED
The operator issued shutdown /r /t 0, forcing an immediate restart. A reboot is a high-risk action for an intruder — it surrenders volatile state and any non-persistent foothold — so issuing one minutes into an intrusion reads as a deliberate human decision, most plausibly to force pending installation or persistence state to take effect.
This is the earliest unambiguous evidence in the record that a person, not a script, was driving the session.
27 Aug 15:02 — Credential Access & Stealer Deployment DETECTED
LSASS access was observed, and the XFiles / OmniStealer information stealer was detected on the host. Roughly half an hour separates first execution from credential-theft activity — a compressed, businesslike tempo consistent with an operator working a known playbook rather than exploring an unfamiliar environment.
27 Aug 17:21 — Collection Staged for Exfiltration DETECTED
A password-protected archive was staged in the Downloads folder. Archiving before exfiltration is routine tradecraft; the password protection additionally defeats content inspection on the way out and complicates DLP matching on the archive body.
28–29 Aug — Dormancy NO ACTIVITY OBSERVED
No operator activity was recorded for approximately three days. Because the sensors were live and comprehensive throughout, this is a genuine absence rather than a visibility gap — an important distinction that ordinary incident reconstruction almost never gets to make. The reason for the pause is not recoverable from telemetry: a shift rotation, a tasking queue, a deliberate dwell, and simple operator absence are all consistent with the evidence.
Recorded as UNKNOWN rather than DETECTED because what is known is the absence of activity, not the cause of it.
30 Aug 14:05 – 14:11 — Return as SYSTEM & Toolchain Build-Out DETECTED
The operator returned and resumed hands-on-keyboard activity as SYSTEM. At 14:09 PowerShell downloaded and installed Python 3.14 machine-wide; at 14:11 SvcHostUpdate.py --deploy was executed and pip installed requests, pyperclip, mss and Pillow. Those four packages map cleanly onto the stealer's functions: HTTP exfiltration, clipboard theft, screen capture and image handling.
Installing a language runtime machine-wide is loud, slow and permanent — an operator trading stealth for capability, and a strong indicator of confidence that nobody was watching.
30 Aug 14:12 — Triple Persistence Under a Microsoft Alias DETECTED
Three persistence mechanisms were planted within the same minute — a scheduled task, a registry Run key, and a Startup-folder launcher — all named MicrosoftCLROptimization after a genuine Microsoft .NET runtime optimisation component, with the payload path reaching into a CLR_v4.0\Optimization directory structure to complete the disguise.
Three redundant mechanisms under one name is a trade-off: it survives the removal of any single mechanism, but it also means one recognised name burns all three at once.
30 Aug 14:12 → 3 Sep — Exfiltration & Wallet Targeting DETECTED
The stealer began POSTing to 150.251.113[.]223:8443 using rotating browser user agents to blend exfiltration into ordinary web traffic. Separately, traffic to Ethereum RPC endpoints — 1rpc[.]io, ethereum-rpc.publicnode[.]com and eth.drpc[.]org — confirmed cryptocurrency wallet interest alongside credential and source-code collection. The operation ran to approximately 167 hours before concluding on 3 September.
Wallet RPC lookups are the clearest signal of the DPRK revenue motive underneath the developer-targeting lure.

Defender Post-Mortem Inverted: nothing was missed — so the question becomes what full visibility does and does not buy
ENTIRE CHAIN
OBSERVED
This case file is the control condition for every other incident in this library. Defenders held complete endpoint, network and decrypted-C2 telemetry before the adversary arrived, so every phase carries a DETECTED badge. Read the other case files against this one: where they show BLIND phases, the difference is almost never adversary sophistication — it is sensor coverage and retention.
TLS DECRYPTION
DECISIVE
TLS-decrypted command and control is what separates this record from flow-based reporting. Without it the team would have had connection metadata to 150.251.113[.]223:8443 and nothing about what crossed the wire. Rotating browser user agents were specifically chosen to survive metadata-level inspection — and they would have.
PERSISTENCE
WOULD LIKELY SURVIVE ELSEWHERE
The MicrosoftCLROptimization naming was caught here because instrumentation flagged the writes mechanically, not because the name looked wrong. A human reviewing a scheduled-task list in a real enterprise would very plausibly skip it — it impersonates a component that genuinely exists, in a path that genuinely exists. The honest finding is that this evasion was neutralised by telemetry, not defeated on its merits.
LOUD ACTIONS
ONLY LOUD IF WATCHED
A machine-wide Python 3.14 install, an interactive reboot, and LSASS access inside 30 minutes are all high-signal events. The operator performed them without hesitation, which implies confidence that nobody was looking — a reasonable assumption against most developer endpoints, where these actions are either unmonitored or indistinguishable from normal developer behaviour.
LIMIT
ATTRIBUTION UNRESOLVED
Total host visibility did not produce operator identity, tasking, or organisational placement. Attribution still rests on tradecraft and tooling overlap with prior PolinRider reporting, at [MEDIUM] confidence. Deception buys behavioural fidelity, not identity — a limit worth stating plainly, because the richness of the telemetry invites over-reading.
LIMIT
DORMANCY UNEXPLAINED
The three-day gap is confirmed as a real absence rather than a sensor gap, but its cause is not recoverable. Shift rotation, tasking queue, deliberate dwell and operator absence all fit equally. A single observation cannot establish a pattern; several engagements would be needed to test whether the return interval is structural.
TRANSFERABLE
DETECTION SURFACE
The durable output for ordinary enterprises is behavioural, not indicator-based: developer tooling spawning curl/cmd.exe, a language runtime installed machine-wide outside change control, three same-named persistence mechanisms appearing within one minute, and outbound POSTs to a raw IP on a non-standard port. None of these depend on the specific addresses in Section 06 surviving rotation.

Consequences Strategic · Technical · Legal/Regulatory
⬡ Strategic / Intelligence
The consequences here run in the defenders' favour, which is the point. The engagement produced first-party behavioural intelligence on an active DPRK campaign — engagement tempo, hands-on-keyboard markers, persistence naming convention and live infrastructure — at the cost of one decoy workstation. It also produced a rare measurable data point on adversary attentiveness: three hours from install to human engagement, which is not obtainable from post-hoc forensics at all.
⬡ Technical / Capability
Full tradecraft capture across the chain, including TLS-decrypted C2 content that flow-level monitoring would have missed entirely. The behavioural detection surface in Section 05 transfers directly to production environments, and the Suricata/ETPRO signatures that fired provide immediately deployable network coverage. No capability was lost — the adversary spent tooling and live infrastructure against a target that never held anything real.
⬡ Legal / Regulatory
Not applicable — no real organisation, users, or regulated data were involved at any point. No breach notification obligation, no regulatory exposure, and no third-party harm arose from this engagement. The decoy persona, company and documents were synthetic by construction.

Attribution rests on tradecraft and tooling consistency rather than on anything the telemetry uniquely revealed about the operator. The lure model (trojanized developer package delivered through a supply-chain vector), the malware families (OtterCandy/RATatouille for C2, OmniStealer for collection), the wallet-RPC targeting, and infrastructure continuity with previously published PolinRider reporting all point the same direction. That is a reasonable [MEDIUM] — and the originating researchers' own stated confidence, which this card carries forward rather than inflating.

Worth stating plainly: total host visibility did not improve attribution. The instrumentation resolved what the operator did to a granularity almost no incident report achieves, and resolved who the operator was not at all. Deception environments yield behavioural fidelity; identity still requires the things it always required — infrastructure overlap with known-attributed indicators, operational security failures, or law-enforcement access. The volume of detail in this case file should not be mistaken for attributional strength.

Open item for the companion actor card. Several third-party sources covering PolinRider describe an overlap between Famous Chollima and APT37 (Reaper/ScarCruft). This project's WaterPlum card does not currently reflect that claim, and this card does not adopt it — APT37 is conventionally attributed to the Ministry of State Security lineage rather than the 313 General Bureau named in the September 2026 joint advisory, so the two claims are not trivially compatible. 09
Historical Significance

This case file's significance is methodological rather than consequential. Nobody was harmed, nothing was lost, and the malware was already documented. What is unusual is the evidentiary basis: a complete intrusion recorded by defenders who instrumented the environment before the adversary arrived, including decrypted command and control. Nearly every other case file in this library — Cyclops Blink, NotPetya, Colonial Pipeline — was reconstructed backwards from artifacts that survived, with the gaps filled by inference. This one was recorded forwards.

That inversion is worth preserving deliberately, because it supplies a baseline the other case files can be measured against. When a case file shows BLIND phases, this one demonstrates that the blindness was usually a property of the sensor coverage rather than of the adversary's skill. The PolinRider operator here was not notably stealthy — a machine-wide runtime install, an interactive reboot, LSASS access within half an hour, and three persistence mechanisms in one minute are all loud. They go unnoticed in ordinary environments because nothing is listening at that granularity, not because they are subtle.

The engagement also produces a genuinely novel class of metric. "Three hours from bait to hands-on-keyboard" measures the adversary's responsiveness, not the defender's — and it implies an operator actively working a queue of fresh installs rather than batch-processing stolen output later. Dwell time, the metric the industry actually tracks, describes how long defenders took to notice. Engagement time describes how much the adversary cares. Only deception environments can produce it, and it is the kind of number that should shape how urgently a developer who ran an untrusted package is treated: not "we have days," but "someone may already be typing."

Finally, a note on the intelligence supply chain itself. This card is a synthesis of a first-party report — our sourcing is one step removed from the sensors, and that degrades what we can claim. The originating researchers watched the operator work; we read their account of it. That distinction is invisible in most finished intelligence, which is precisely why it is worth writing down.
