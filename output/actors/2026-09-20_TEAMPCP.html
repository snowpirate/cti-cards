Overview

TeamPCP is a financially motivated, cloud-native cybercriminal operation that in 2026 ran what several vendors independently describe as the most consequential open-source software supply chain campaign of the year (Flare, Feb 2026; SocRadar, 2026). Rather than attacking victims directly, the group compromises the trusted upstream software — security scanners, AI gateways, SDKs — that thousands of organizations pull into their build pipelines, converting a single maintainer's stolen credential into a cascading compromise of everyone downstream. Its defining trait is not technical novelty: initial access, credential theft, and typosquatting are all long-understood techniques. The distinguishing feature is industrialized scale — automated worm-driven scanning of exposed Docker APIs, Kubernetes clusters, and CI/CD endpoints, chained across five separate software ecosystems (GitHub Actions, Docker Hub, PyPI, npm, and OpenVSX) in a matter of weeks (Bitsight, Jul 2026).

TeamPCP matters right now because its trajectory illustrates where financially motivated cybercrime is heading: from a Telegram-based stolen-data brokerage in mid-2025 into a full-spectrum initial-access-broker-plus-ransomware operation. The group's March 2026 compromise of Aqua Security's Trivy, Checkmarx's KICS, and BerriAI's LiteLLM — an AI gateway with over 95 million monthly downloads — rippled outward to breach the European Commission's AWS environment (roughly 500,000 credentials and 300+ GB exfiltrated, per CERT-EU/The Record, 2026) and to touch automotive manufacturers including BMW, Audi, Honda, Mercedes-Benz, Volvo, and Toyota through their software supply chains (TechCrunch, Aug 2026).

Within the current eCrime landscape, TeamPCP sits at the convergence point of two trends analysts have flagged as accelerating through 2026: supply-chain compromise as a scalable initial-access vector, and the blurring line between access brokers and ransomware operators. Since a formal partnership announced in late March 2026, TeamPCP supplies stolen cloud and CI/CD access to the Vect ransomware operation for encryption and extortion, while simultaneously running its own CipherForce extortion brand for direct operations — a dual-track monetization model that maximizes return on every compromised credential (Sophos, 2026; Hard2Bit, 2026).

The critical operational context as of this compile date is the August 27, 2026 arrest of two alleged members in Western Australia and a parallel U.S. federal indictment (DOJ, N.D. Cal.) — a meaningful law-enforcement milestone, but one researchers assess as only partial disruption. TeamPCP is widely characterized as a loose confederation drawing from multiple cybercriminal circles rather than a single hierarchical cell (BleepingComputer, Aug 2026), and its decentralized, blockchain-backed C2 infrastructure was explicitly engineered for resilience against takedown.

Two developments since the previous compile materially change the picture. First, the group did not stop after March: on May 11, 2026 it launched Mini Shai-Hulud, a genuinely self-propagating cross-ecosystem worm that poisoned over 170 npm and PyPI packages in a single coordinated push — including the TanStack, Mistral AI and OpenSearch ecosystems — by stealing an OIDC token from a CI runner and exchanging it for publish rights to an entire namespace (Expel; StepSecurity; Phoenix Security, May 2026). That campaign escalates TeamPCP from "compromises packages" to "operates a worm," and its credential stealer reached beyond cloud keys into HashiCorp Vault tokens and Kubernetes secrets while injecting persistence hooks into developer tooling including VS Code and Claude Code.

Second, Flare's Emerging Threats Team published the OSINT chain that identified an alleged operator — a rare, fully documented walkthrough of how reused identity artifacts across a decade collapsed an operator's separation between criminal persona and real life. That material is captured in §10 (OPSEC Procedures) as observed OPSEC failure, and it raises this card's confidence on group structure from the [MEDIUM] the previous compile assigned.

03
Attack Lifecycle Supply Chain Compromise → Cloud Credential Harvesting → Dual-Track Extortion

TeamPCP's entry point is almost never the eventual victim organization — it is a trusted upstream maintainer or CI/CD credential. The group has repeatedly exploited incomplete credential rotation and stale GitHub Personal Access Tokens tied to security-tooling maintainers, most notably against the Aqua Security Trivy project (Unit 42, Apr 2026), alongside opportunistic exploitation of CVE-2025-55182 ("React2Shell"), a CVSS 10.0 unauthenticated RCE in React Server Components, to gain footholds in exposed cloud-hosted applications. Reconnaissance is largely automated and worm-driven, scanning for exposed Docker APIs, Kubernetes clusters, and CI/CD endpoints at internet scale (Flare, Feb 2026).

Once inside a maintainer's account or pipeline, the group force-pushes malicious commits across historical release tags — in the Trivy compromise, 76 of 77 version tags on aquasecurity/trivy-action were overwritten, alongside every tag on aquasecurity/setup-trivy, so any downstream consumer pinning to a "stable" tag silently pulled trojanized code (Unit 42, Apr 2026). A parallel technique injects malicious pre/post-install scripts into package.json across dozens of npm packages and drops .pth files into Python packages for automatic execution at interpreter startup — the mechanism used to trojanize LiteLLM (95M+ monthly downloads) and the Telnyx SDK. Persistence inside compromised infrastructure is sustained through CanisterWorm, a self-propagation module spreading laterally across the npm/PyPI ecosystem, and kube.py, a secondary-stage payload deployed as a Kubernetes DaemonSet that masquerades as systemd or a PostgreSQL monitor (pgmon) process.

TeamPCP's primary payload, the "kamikaze.sh" cloud stealer, bypasses GitHub's secret-masking controls by reading CI runner process memory directly (/proc/<pid>/mem) to recover plaintext tokens, then harvests AWS/GCP/Azure credentials via cloud Instance Metadata Service abuse, plus Kubernetes secrets, SSH keys, CI/CD tokens, and LLM API keys. Command and control is deliberately resilient: primary infrastructure includes typosquatted domains such as scan.aquasecurtiy[.]org and a decentralized Internet Computer Protocol (ICP) blockchain "canister" acting as a tamper-proof dead drop, backstopped by hidden GitHub repositories created inside victim organizations (e.g., docs-tpcp) as a fallback channel engineered to survive infrastructure takedown.

Stolen data is encrypted client-side with AES-256-CBC under an embedded 4096-bit RSA public key, then smuggled out via WAV-file steganography (hangup.wav on Windows, ringtone.wav on Linux) before landing on TeamPCP-controlled infrastructure. From there the group monetizes on two parallel tracks: direct extortion under its own CipherForce leak-site brand, and — since the March 2026 partnership — supplying stolen access to the Vect ransomware operation for encryption and BreachForums-affiliate-driven extortion, functioning as a de facto initial-access broker for a second criminal ecosystem.

06
Tools, Malware & Infrastructure
KAMIKAZE.SH ("TeamPCP Cloud Stealer") STEALER · CUSTOM · Unit 42
Primary credential-harvesting payload deployed via poisoned packages; at least 3 documented versions. Reads CI runner process memory via /proc/<pid>/mem to bypass GitHub secret masking, then extracts AWS/GCP/Azure tokens, SSH keys, Kubernetes configs, CI/CD secrets, and LLM API keys from .env files. Output is encrypted (AES-256-CBC/RSA-4096) before exfiltration. Detection artifact: outdated git/2.43.0 client and TruffleHog secret-validation signatures in outbound CI traffic.
CANISTERWORM WORM / C2 · CUSTOM · Unit 42
Self-propagating module that spreads laterally across the npm and PyPI package ecosystems. Its distinguishing architecture element is use of a decentralized Internet Computer Protocol (ICP) blockchain "canister" (tdtqy-oyaaa-aaaae-af2dq-cai.raw.icp0[.]io) as a tamper-proof C2 dead drop, making primary infrastructure resistant to conventional domain/IP takedown.
MINI SHAI-HULUD SELF-PROPAGATING WORM · CUSTOM · Expel / StepSecurity
Cross-ecosystem npm/PyPI worm deployed 2026-05-11, named for the sandworms of Frank Herbert's Dune — part of a consistent Dune-themed naming convention across the group's infrastructure. Propagates by hijacking GitHub Actions workflows to forge valid publish tokens, notably by extracting OIDC tokens from CI runner processes where trust federation with npm remains configured. Its stealer reaches beyond cloud keys into HashiCorp Vault tokens and Kubernetes secrets, and it injects persistence hooks into developer tooling — VS Code and Claude Code — so that compromise survives reboot and follows the developer rather than the machine. C2 via api.masscan[.]cloud and filev2.getsession[.]org. The May wave alone reached 170+ packages; a later AntV maintainer compromise added 300+ more.
KUBE.PY LOADER / SECONDARY STAGE · CUSTOM · Unit 42
Kubernetes-focused secondary payload deployed as a DaemonSet for cluster-wide reach. Masquerades as systemd or a PostgreSQL monitor (pgmon) process to evade casual process review; used for scheduled re-execution and Kubernetes secrets harvesting.
NORD STREAM LOLBIN / OFFENSIVE TOOLING (REPURPOSED) · OSS · Wiz
Publicly available GitHub-exploitation/red-team framework repurposed to create and manipulate malicious GitHub Actions workflows at scale; observed with the tool's default branch-naming pattern (dev_remote_ea5Eu/test/v1) left unmodified in victim repositories — a useful detection artifact.
CIPHERFORCE RANSOMWARE / EXTORTION LOCKER · CUSTOM · Sophos / Hard2Bit
Proprietary data-leak and extortion brand operated directly by TeamPCP, run in parallel with the Vect affiliate program. TeamPCP has publicly stated it uses only CipherForce for its own encryption operations, distancing itself from a documented flaw in Vect's locker.
VECT RANSOMWARE RAAS · THIRD-PARTY PARTNER · Sophos / Jumpsec
External ransomware-as-a-service TeamPCP formally partnered with in late March 2026, supplying stolen access in exchange for BreachForums-affiliate-driven encryption and extortion at scale. Jumpsec (Apr 2026) documented a critical implementation flaw in Vect's locker that permanently destroys, rather than encrypts, files larger than 128KB.

TeamPCP represents the industrialization of software supply-chain compromise as a criminal business model rather than a technical leap forward. Every individual technique observed — RCE exploitation, PAT theft, typosquatting, package-lifecycle-hook abuse — is well-precedented; what sets the group apart is disciplined reuse of these techniques chained across five ecosystems (GitHub Actions, Docker Hub, PyPI, npm, OpenVSX) within a single multi-week campaign window, and a monetization structure (dual CipherForce/Vect tracks) built to extract value from every credential harvested, whether or not a given victim is worth a bespoke ransomware deployment.

The group's most dangerous capability is blast radius, not sophistication. The LiteLLM compromise alone touched a package with over 95 million monthly downloads; a single stolen maintainer credential compounded into confirmed or claimed impact against 2,500+ organizations, an EU institution, and multiple automotive OEMs. This dynamic — narrow initial access, broad downstream consequence — is structurally difficult for individual victim organizations to defend against, since the compromise arrives through a trusted update channel rather than a perimeter they control.

Attribution to the TeamPCP brand for the core March–August 2026 campaign is [HIGH] confidence, cross-corroborated by independent vendor telemetry (Wiz, Unit 42, KELA/UNC6780, CrowdStrike/Altered Spider) and now reinforced by criminal charges. Confidence on the group's internal structure remains [MEDIUM]: multiple outlets describe TeamPCP as a loose confederation of individuals drawn from several existing cybercriminal circles rather than a single hierarchical cell, which is consistent with an arrest netting only two individuals against a campaign of this scale. A competing hypothesis worth flagging explicitly: some claimed victims (Databricks, and possibly AstraZeneca — separately linked by some researchers to LAPSUS$) may reflect opportunistic claim-jacking on leak forums rather than confirmed TeamPCP operations, and should not be treated as confirmed without independent forensic corroboration. This assessment would move to [HIGH] on structure if unsealed court filings conclusively map the "DMT"/PersyPCP Telegram personas to the named defendants.

Updated 2026-09-20 — two revisions to the assessment above. First, "blast radius, not sophistication" now understates the capability. The May 2026 Mini Shai-Hulud campaign was genuinely self-propagating: it forged its own publish tokens by extracting OIDC credentials from CI runners and spread without operator intervention, which is a materially different threat model from the March campaign's hands-on package poisoning. Injecting persistence into VS Code and Claude Code is the sharper development — it attaches compromise to the developer rather than the host, and survives the rebuild that would normally close out an incident. Second, the persona-to-individual gap this card previously flagged has substantially closed for one operator via Flare's published OSINT chain, though full group structure remains [MEDIUM] and the disputed Databricks/AstraZeneca claims are unchanged.

Forward risk trajectory: the August 2026 arrests are unlikely to fully neutralize the group given its loose, multi-member structure and infrastructure explicitly engineered for resilience — a decentralized ICP blockchain C2 channel and GitHub-repository fallback dead drops are both designed to survive conventional takedown. Expect continued targeting of security and DevSecOps tooling as a high-leverage vector (compromising the tools defenders trust is more efficient than defeating them), and continued Vect/BreachForums-affiliate monetization even if the CipherForce-specific operators identified in this action go dark.

10
OPSEC Procedures Observed infrastructure hygiene, persona management, anti-forensics
Persona Management — Catastrophic Failure [HIGH]
The defining OPSEC characteristic of this actor is not what it did well but what it did not do at all: maintain separation between criminal and personal identity. A single handle, DeadCatx3, was reused across a GitHub tooling account, a HackerOne profile carrying a real name, and a Hugging Face account whose listed domain (masscan[.]cloud) later served as operational C2. The chain terminated in an avatar — a distinctive cat-before-monitors image, original enough that reverse image search returned nothing — that appeared on both a decade-old Steam profile and the TeamPCP Telegram channel. Reverse image search returning zero results is what made it decisive: a stock image would have proved nothing (Flare, Sep 2026).
Credential Hygiene — Self-Inflicted [HIGH]
The pivot from handle to real identity ran through the actor's own exposure in breach corpora: leaked passwords tied a school email address to a personal Gmail account, which in turn owned the TikTok profile displaying both a real name and a Steam reference. An operator who built a career on harvesting other people's credentials was located through his own appearance in a combolist — worth stating plainly, because the same corpora are available to defenders.
Infrastructure Rotation — Mixed [MEDIUM]
Operationally the group showed reasonable discipline: commercial VPN egress (Mullvad exits via Datacamp and 31173 Services AB), disposable VPS hosting (InterServer), and rapid rotation of staging domains across the March campaign. The failure was linkage, not rotation — masscan[.]cloud appeared on a personal Hugging Face profile and was later reused as Mini Shai-Hulud C2 infrastructure, connecting operational tooling directly to an identity artifact. Rotating infrastructure does not help if one asset bridges both lives.
Tooling Hygiene — Weak [MEDIUM]
Several avoidable fingerprints survived into victim environments: the Nord Stream framework's default branch-naming pattern (dev_remote_ea5Eu/test/v1) left unmodified in poisoned repositories, an outdated git/2.43.0 client string, and Boto3 requests carrying Kali Linux default signatures (Wiz, Mar 2026). Each is a free detection opportunity handed to defenders, and each suggests operators running stock tooling without sanitising defaults.
Anti-Takedown Resilience — Strong [HIGH]
In deliberate contrast to its personal OPSEC, the group's infrastructure design was genuinely takedown-resistant: a decentralized Internet Computer Protocol blockchain canister served as a tamper-proof C2 dead drop immune to conventional domain seizure or registrar action, with GitHub repository fallbacks behind it. This asymmetry — sophisticated operational architecture, negligent personal tradecraft — is the most instructive thing about the group, and it is the reason arrests were possible while infrastructure disruption was not.

Detection Evasion Specific techniques, loader internals, EDR bypass patterns
Strategic Pre-Emption — Compromise the Scanners First T1195.002 / T1562
DETECTION SUPPRESSION Trivy · Checkmarx KICS
The group's highest-leverage evasion decision was target selection rather than tooling: by poisoning vulnerability scanners and security actions first, it simultaneously disabled the detection layer and inherited that layer's privileged access to downstream pipelines. Defensive tooling runs early, runs with credentials, and is trusted by definition.
Trivy workflow compromise: CVE-2026-33634 exploited to overwrite 76 of 77 versions of the automated workflow using a stolen developer credential with repository write access (CSA Labs, Mar 2026). Checkmarx KICS GitHub Action compromised 2026-03-23.
Loader Anti-Analysis — API Hashing, Direct Syscalls, ETW Blinding T1027 / T1562.006
EDR BYPASS TELEMETRY LOSS
The Windows loader resolves APIs by DJB2 hash rather than name (defeating static import analysis), issues direct syscalls to bypass userland API hooking, and kills Event Tracing for Windows to blind the telemetry channel EDR products depend on.
Observed techniques: DJB2 hash-based API resolution; direct syscall invocation; ETW patching/termination. Specific syscall stubs and hash constants vary per build and are not published as stable indicators.
Automated Re-Obfuscation Against Signatures T1027.005
SIGNATURE EVASION
Analysed variants share identical architecture and an identical cipher seed while differing in class names and lookup tables — the signature of an automated re-obfuscation pipeline producing a fresh-looking sample per deployment. Hash- and string-based detection degrades to near-useless against this; the invariant is the architecture, not the bytes.
Invariant across variants: identical architecture, identical cipher seed. Variable per build: class names, lookup tables. Detection implication — pivot to behavioural and structural signatures (e.g. YARA on architecture/constants) over file hashes.
PNG-Steganographic Shellcode & Process Hollowing T1027.003 / T1055.012
EDR BYPASS dllhost.exe
The final stage injects an embedded payload into a created dllhost.exe via process hollowing. The shellcode is carried as an embedded PNG image: each ARGB pixel encodes a byte, with 0xFF as separator — meaning the payload never exists as recognisable code on disk. The group used the same steganographic instinct for exfiltration, with hangup.wav / ringtone.wav as carriers (Unit 42).
Shellcode encoding: embedded PNG, each ARGB pixel = one byte, 0xFF separator. Injection target: newly created dllhost.exe (process hollowing). Final payload function: RAT backdoor.
Blockchain C2 Resolution T1102 / T1568
NETWORK ICP canister
CanisterWorm resolves command and control through an Internet Computer Protocol blockchain canister acting as a tamper-proof dead drop. There is no domain to seize and no registrar to serve, and the traffic resembles ordinary Web3 API access — a category most enterprise egress policies neither block nor inspect.
Canister dead-drop: tdtqy-oyaaa-aaaae-af2dq-cai.raw.icp0[.]io Detection approach — treat any egress to ICP canister endpoints from build or server infrastructure as anomalous by default; there is rarely a legitimate reason for CI to talk to a blockchain canister.
Secret-Masking Bypass via Runner Memory T1003 / T1552
SIEM EVASION /proc/<pid>/mem
kamikaze.sh reads CI runner process memory directly via /proc/<pid>/mem, defeating GitHub's secret-masking protection — which redacts secrets in logs but cannot protect them in the memory of the process using them. Exfiltration is AES-256-CBC/RSA-4096 encrypted before egress, so content inspection yields nothing.
Read path: /proc/<pid>/mem against the runner process. Encryption before exfil: AES-256-CBC / RSA-4096. Residual detection artifacts (per Wiz): outdated git/2.43.0 user agent and TruffleHog secret-validation signatures in outbound CI traffic.
